Задача 1. Ввод возраста при регистрации

Вы пишете форму регистрации. Пользователь вводит возраст, и программа должна переспрашивать, пока не получит нормальное значение.

Требования:

  • если ввели не число ("двадцать", "abc"), выведите «Введите число цифрами» и спросите снова;
  • если число меньше 0 или больше 120, выведите «Некорректный возраст» и спросите снова;
  • когда возраст корректный, выведите «Регистрация продолжена, возраст: N».

Пример работы:

code
Введите возраст: abc
Введите число цифрами
Введите возраст: -3
Некорректный возраст
Введите возраст: 25
Регистрация продолжена, возраст: 25

Подсказка: понадобятся while True, try/except ValueError и break.

Показать решение
python
while True:
    try:
        age = int(input("Введите возраст: "))
    except ValueError:
        print("Введите число цифрами")
        continue  # возвращаемся в начало цикла и спрашиваем снова

    if age < 0 or age > 120:
        print("Некорректный возраст")
        continue

    break  # сюда попадаем только с корректным возрастом

print(f"Регистрация продолжена, возраст: {age}")

Разбор:

  • В try лежит только одна строка, которая реально может упасть (int(...)). Проверка диапазона вынесена наружу, потому что это обычная логика, а не исключение.
  • continue внутри except нужен обязательно. Без него код пошёл бы дальше, к if age < 0, а переменной age не существует, потому что int() упал.

Задача 2. Корзина интернет-магазина

Есть каталог с ценами и корзина пользователя:

python
PRICES = {"хлеб": 50, "молоко": 90, "сыр": 400}

cart = [
    {"item": "хлеб", "qty": "2"},
    {"item": "молоко", "qty": "1"},
    {"item": "колбаса", "qty": "1"},
    {"item": "сыр", "qty": "много"},
    {"item": "сыр", "qty": "3"},
]

Напишите функцию calculate_total(cart), которая считает итоговую сумму заказа. Позиции с ошибками она пропускает и сообщает, что не так.

Ожидаемый вывод:

code
Товар 'колбаса' не найден в каталоге — пропущен
Некорректное количество у 'сыр': 'много' — пропущен
Итого: 1390

💡 Подсказка: здесь возникнут два разных типа ошибок, и каждый нужно ловить отдельно. Подумайте, какие именно.

Показать решение
python
PRICES = {"хлеб": 50, "молоко": 90, "сыр": 400}

cart = [
    {"item": "хлеб", "qty": "2"},
    {"item": "молоко", "qty": "1"},
    {"item": "колбаса", "qty": "1"},
    {"item": "сыр", "qty": "много"},
    {"item": "сыр", "qty": "3"},
]


def calculate_total(cart):
    total = 0
    for position in cart:
        name = position["item"]
        qty_text = position["qty"]

        try:
            price = PRICES[name]   # может упасть с KeyError
            qty = int(qty_text)    # может упасть с ValueError
        except KeyError:
            print(f"Товар '{name}' не найден в каталоге — пропущен")
        except ValueError:
            print(f"Некорректное количество у '{name}': '{qty_text}' — пропущен")
        else:
            # выполняется только если в try не было ошибки
            total += price * qty

    return total


print("Итого:", calculate_total(cart))

Разбор:

  • KeyError возникает, когда товара нет в словаре PRICES, а ValueError — когда int() не может превратить строку в число.
  • Сумма прибавляется в else, чтобы это происходило только при успешном разборе позиции.
  • Ошибки обрабатываются внутри цикла, поэтому одна плохая позиция не ломает подсчёт всей корзины. Если бы try стоял вокруг всего цикла, после первой ошибки подсчёт бы просто остановился.

Задача 3. Валидатор пароля

Напишите функцию validate_password(password), которая выбрасывает ValueError с понятным сообщением, если:

  • пароль короче 8 символов;
  • в нём нет ни одной цифры;
  • в нём нет ни одной заглавной буквы.

Если всё хорошо, функция возвращает True.

Затем проверьте список паролей:

python
passwords = ["123", "password", "Password", "Password1"]

Ожидаемый вывод:

code
'123': пароль короче 8 символов
'password': нет ни одной цифры
'Password': нет ни одной цифры
'Password1': ок

💡 Подсказка: сама validate_password ничего не печатает, она только делает raise ValueError("..."). Печатает тот, кто её вызвал, в блоке except ValueError as e.

Показать решение
python
def validate_password(password):
    if len(password) < 8:
        raise ValueError("пароль короче 8 символов")

    has_digit = False
    has_upper = False
    for ch in password:
        if ch.isdigit():
            has_digit = True
        if ch.isupper():
            has_upper = True

    if not has_digit:
        raise ValueError("нет ни одной цифры")
    if not has_upper:
        raise ValueError("нет ни одной заглавной буквы")

    return True


passwords = ["123", "password", "Password", "Password1"]

for pwd in passwords:
    try:
        validate_password(pwd)
    except ValueError as e:
        print(f"'{pwd}': {e}")
    else:
        print(f"'{pwd}': ок")

Разбор:

  • raise сразу останавливает функцию, поэтому после первой найденной проблемы остальные проверки не выполняются.
  • Функция сообщает о проблеме, а решает, что с ней делать, вызывающий код. Эту же функцию можно использовать и в консольной программе, и на сайте, и в телеграм-боте, меняя только обработку в except.
  • Короткий вариант проверки, если уже знакомы с any: has_digit = any(ch.isdigit() for ch in password).

Задача 4. Загрузка конфига приложения

Создайте рядом со скриптом файл config.json:

json
{"host": "localhost", "port": "8080", "debug": true}

Напишите функцию load_config(path), которая читает файл и возвращает словарь, где port уже превращён в int.

Если что-то не так, функция выбрасывает ValueError с понятным текстом, используя raise ... from e:

Ситуация Сообщение
файла нет Файл настроек не найден: config.json
файл не является корректным JSON Файл настроек повреждён
нет ключа port В настройках нет параметра port
port не число port должен быть числом

В main() поймайте ValueError, выведите сообщение и запустите «приложение» с настройками по умолчанию: {"host": "localhost", "port": 8000, "debug": False}.

Проверьте все 4 случая, по очереди портя файл.

Подсказка: суть задачи в том, чтобы превратить четыре разные технические ошибки (FileNotFoundError, json.JSONDecodeError, KeyError, ValueError) в одну понятную. Тогда main() нужно ловить только один тип ошибки.

Показать решение
python
import json

DEFAULT_CONFIG = {"host": "localhost", "port": 8000, "debug": False}


def load_config(path):
    # Шаг 1: прочитать файл
    try:
        with open(path, encoding="utf-8") as f:
            config = json.load(f)
    except FileNotFoundError as e:
        raise ValueError(f"Файл настроек не найден: {path}") from e
    except json.JSONDecodeError as e:
        raise ValueError("Файл настроек повреждён") from e

    # Шаг 2: проверить и преобразовать port
    try:
        config["port"] = int(config["port"])
    except KeyError as e:
        raise ValueError("В настройках нет параметра port") from e
    except (ValueError, TypeError) as e:
        raise ValueError("port должен быть числом") from e

    return config


def main():
    try:
        config = load_config("config.json")
    except ValueError as e:
        print("Ошибка конфигурации:", e)
        print("Запускаю с настройками по умолчанию")
        config = DEFAULT_CONFIG

    print(f"Сервер запущен на {config['host']}:{config['port']}")


main()

Как проверить все случаи:

  1. Переименуйте config.json → «файл не найден».
  2. Удалите закрывающую скобку } → «файл повреждён».
  3. Удалите "port": "8080", → «нет параметра port».
  4. Замените "8080" на "abc" → «port должен быть числом».

Разбор:

  • from e сохраняет исходную ошибку: при отладке в traceback будет видна и настоящая причина, и ваше понятное сообщение.
  • TypeError тоже ловится, потому что int(None) или int([1, 2]) падают именно с ним, а в JSON вместо строки могут положить null или список.
  • Тонкость: json.JSONDecodeError является наследником ValueError. Поэтому без перехвата внутри load_config он всё равно поймался бы в main(), но с непонятным техническим текстом. Именно для этого мы и заменяем его своим сообщением.
  • Чтение файла и проверка port разнесены по двум try. Так каждый try маленький, и сразу понятно, какая строка может упасть.

Задача 5. Перевод денег между счетами

python
accounts = {"alice": 1000, "bob": 500}
  1. Напишите transfer(from_user, to_user, amount), которая:
    • выбрасывает KeyError("Счёт не найден: имя"), если любого из пользователей нет;
    • выбрасывает ValueError("Сумма должна быть больше нуля"), если amount <= 0;
    • выбрасывает ValueError("Недостаточно средств"), если денег не хватает;
    • иначе переводит деньги.
  2. Напишите обёртку safe_transfer(from_user, to_user, amount), которая вызывает transfer, при любой ошибке (KeyError или ValueError) пишет в «журнал» строку [ЛОГ] Неудачный перевод alice → bob: <текст ошибки> и пробрасывает ошибку дальше голым raise.
  3. В main() выполните несколько переводов, включая ошибочные, и ловите KeyError и ValueError отдельно, с разными сообщениями пользователю.
python
safe_transfer("alice", "bob", 300)     # успешно
safe_transfer("alice", "carl", 100)    # нет такого счёта
safe_transfer("bob", "alice", 5000)    # не хватает денег
safe_transfer("alice", "bob", -50)     # отрицательная сумма

В конце выведите итоговые балансы и проверьте, что после неудачных переводов они не изменились.

Звёздочка сверху: представьте, что деньги уже списались с отправителя, а при зачислении получателю произошла ошибка. Сделайте так, чтобы в этом случае списание откатывалось.

Показать решение (основная часть)
python
accounts = {"alice": 1000, "bob": 500}


def transfer(from_user, to_user, amount):
    if from_user not in accounts:
        raise KeyError(f"Счёт не найден: {from_user}")
    if to_user not in accounts:
        raise KeyError(f"Счёт не найден: {to_user}")
    if amount <= 0:
        raise ValueError("Сумма должна быть больше нуля")
    if accounts[from_user] < amount:
        raise ValueError("Недостаточно средств")

    accounts[from_user] -= amount
    accounts[to_user] += amount


def safe_transfer(from_user, to_user, amount):
    try:
        transfer(from_user, to_user, amount)
    except (KeyError, ValueError) as e:
        print(f"[ЛОГ] Неудачный перевод {from_user} → {to_user}: {e.args[0]}")
        raise  # записали в журнал, а решать, что делать, будет main()


def main():
    transfers = [
        ("alice", "bob", 300),
        ("alice", "carl", 100),
        ("bob", "alice", 5000),
        ("alice", "bob", -50),
    ]

    for from_user, to_user, amount in transfers:
        try:
            safe_transfer(from_user, to_user, amount)
        except KeyError as e:
            print("Ошибка: проверьте данные получателя —", e.args[0])
        except ValueError as e:
            print("Перевод отклонён —", e)
        else:
            print(f"Перевод {amount} от {from_user} к {to_user} выполнен")
        print()

    print("Итоговые балансы:", accounts)


main()

Вывод:

code
Перевод 300 от alice к bob выполнен

[ЛОГ] Неудачный перевод alice → carl: Счёт не найден: carl
Ошибка: проверьте данные получателя — Счёт не найден: carl

[ЛОГ] Неудачный перевод bob → alice: Недостаточно средств
Перевод отклонён — Недостаточно средств

[ЛОГ] Неудачный перевод alice → bob: Сумма должна быть больше нуля
Перевод отклонён — Сумма должна быть больше нуля

Итоговые балансы: {'alice': 700, 'bob': 800}

Разбор:

  • Все проверки идут до изменения балансов. Если что-то не так, функция падает раньше, чем успела что-то испортить.
  • safe_transfer ловит ошибку только для записи в журнал, а голый raise отправляет её дальше. Без него main() думал бы, что перевод прошёл успешно, и напечатал бы «выполнен».
  • Почему e.args[0], а не просто e? У KeyError есть особенность: str(KeyError("текст")) возвращает текст в кавычках: 'текст'. e.args[0] достаёт исходную строку без кавычек. У ValueError такой проблемы нет.
Показать решение (звёздочка: откат перевода)

Чтобы смоделировать сбой, вынесем зачисление в отдельную функцию, которая может упасть, например, если «банк получателя недоступен»:

python
accounts = {"alice": 1000, "bob": 500}
bank_online = False  # поменяйте на True, чтобы переводы проходили


def credit(user, amount):
    """Зачисление денег. Может упасть из-за сбоя связи."""
    if not bank_online:
        raise ConnectionError("Банк получателя недоступен")
    accounts[user] += amount


def transfer(from_user, to_user, amount):
    if from_user not in accounts:
        raise KeyError(f"Счёт не найден: {from_user}")
    if to_user not in accounts:
        raise KeyError(f"Счёт не найден: {to_user}")
    if amount <= 0:
        raise ValueError("Сумма должна быть больше нуля")
    if accounts[from_user] < amount:
        raise ValueError("Недостаточно средств")

    accounts[from_user] -= amount  # списали
    try:
        credit(to_user, amount)    # пытаемся зачислить
    except ConnectionError:
        accounts[from_user] += amount  # ОТКАТ: возвращаем деньги отправителю
        raise                          # и пробрасываем ошибку выше


try:
    transfer("alice", "bob", 300)
except ConnectionError as e:
    print("Перевод не выполнен:", e)

print("Балансы:", accounts)  # {'alice': 1000, 'bob': 500} — ничего не потерялось

Разбор:

  • Это классический паттерн «поймал → откатил → пробросил». Функция transfer не знает, что делать со сбоем связи (повторить позже? сообщить пользователю?), но знает, что за собой нужно прибраться. Поэтому она откатывает списание и отдаёт ошибку наверх голым raise.
  • Без отката у alice списались бы 300, а bob их не получил бы. Деньги просто исчезли бы.
  • В реальных системах этим занимаются транзакции базы данных (commit / rollback), но принцип тот же самый.
  • Если хотите, чтобы safe_transfer из основной части тоже логировал этот случай, добавьте ConnectionError в кортеж: except (KeyError, ValueError, ConnectionError) as e:.
